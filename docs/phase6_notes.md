# Phase 6: Testing and stabilization

The quality pass used the existing unit suite, controlled regression cases, Streamlit AppTest interactions, a live browser session, three algorithm demonstrations, a full 20-seed benchmark, and measured small/default/stress runs. The code runs on Windows 11 with Python 3.14.3 and Streamlit 1.56.0. Python 3.11 compatibility is based on supported syntax and the declared dependency range; it was not separately executed in a 3.11 environment.

Core tests cover the 20 unique synthetic locations, ordered IDs, finite Cartesian coordinates, symmetric Euclidean matrix, route validation, and return to warehouse. Controlled tests check the 3-4-5 distance and square perimeter. The new regression suite checks exact OX segment and fill order, an exact swap, independence and validity of every generated population, seed repeatability, disabled-local-search equivalence, and SVG point/edge counts. Existing 2-Opt tests cover crossing removal, zero distances, invalid matrices, and non-worsening results. No global optimum is claimed.

Benchmark tests cover paired seeds, summary statistics, zero denominators, convergence lengths, and JSON/CSV structure. The full benchmark was run from a temporary directory so the saved `results/` files were preserved. It produced 20 GA and 20 hybrid runs with seeds 42–61. NN measured 405.11 units; GA best/mean were 330.60/356.26; hybrid best/mean were 323.67/323.67. Mean algorithm times were 2.348 s for GA and 3.823 s for hybrid on this machine. Timing includes each algorithm's initialization, evolution, and scoring; hybrid also includes local search. Equal GA settings do not mean equal computational effort.

The live browser showed all five navigation choices, the warehouse/destination graphic, a real NN route, and the default hybrid route with its 201-point convergence history. AppTest exercised all sections, each algorithm, and a small benchmark. A regression test checks that choosing Hybrid exposes its local-search controls immediately; another checks that invalid population/tournament settings show an error. CSV helpers verify route return, matrix shape, summaries, and generation indices. Downloads are generated in memory.

Two UI defects were corrected: placing algorithm selection inside the form delayed showing Hybrid controls, and long metric values were truncated at laptop width. The selector now rerenders the relevant form before submission, and compact metric labels leave the synthetic unit visible. The mathematical algorithms and public APIs were unchanged. Existing benchmark files were not overwritten.

Measured run times before these UI changes were: small (20 population, 30 generations) GA 0.055 s and hybrid 0.095 s; default (100, 200) GA 2.216 s and hybrid 3.562 s; stress (150, 300) GA 4.983 s and hybrid 7.909 s. No algorithm optimization was made, so no speedup is claimed. The default demonstrations remain suitable for a classroom presentation; a small benchmark can use 1–3 runs, population 20, and 30 generations.

Remaining limitations: one synthetic 20-location instance, straight-line distances, no traffic or delivery constraints, heuristic solutions without an optimality guarantee, and timing variation across machines. Exact objective-evaluation counts remain unmeasured. The benchmark UI can take minutes with large submitted settings and warns about that cost.
